🏫 Project Overview

What this application is, who it serves, and what problems it solves.

This repository is a full-stack monolith delivered as a Progressive Web App. It serves two distinct purposes under one Vercel deployment:

🏠
USC Official Website (Public)
Public-facing marketing and informational site for the University Student Council of ISUFST Dingle Campus. Contains the homepage, officer roster, events calendar, campus guide (Leaflet map), contact form, and legal pages. Fully accessible without login. Served with layout: 'public' meta tag.
📋
Officer Attendance System (Private)
Role-gated attendance management platform for USC officers. Supports three check-in methods (self-geolocation with Haversine fence, QR HMAC scan, manual staff override), duty scheduling, real-time tracking, CSV export, and offline IndexedDB queue for unstable mobile connections.
Design Philosophy Both halves share the same Vue Router, Pinia stores, and Vercel deployment. Public pages use meta: { layout: 'public' }. Authenticated pages use meta: { requiresAuth: true }. A global route guard enforces this split. The public portal pages at /portal/* are informational marketing for the attendance system itself.

Route Guard Logic

// src/router/index.ts — global beforeEach guard
router.beforeEach(async (to) => {
  // 1. Hydrate auth state from Supabase session on first navigation
  if (!auth.isAuthenticated) await auth.fetchUser()

  // 2. Protected route, not logged in → go to login
  if (to.meta.requiresAuth && !auth.isAuthenticated) return { name: 'login' }

  // 3. Guest route (login), already logged in → go to dashboard
  if (to.meta.guest && auth.isAuthenticated) return { name: 'dashboard' }

  // 4. Role-restricted route, insufficient role → go to dashboard
  if (to.meta.roles && !to.meta.roles.includes(auth.user.role)) return { name: 'dashboard' }

  return true
})

📦 Pinia Stores

All state management. Composition API style. No Options API stores. Located in src/stores/.

🔒 auth.ts — useAuthStore
Manages authenticated session. Wraps Supabase Auth SDK.

State: user: User | null, loading: boolean
Computed: isAuthenticated, isSuperAdmin, isStaff, isClient, role
Actions: login(), logout(), fetchUser(), updateProfile()
📅 events.ts — useEventsStore
Manages USCEvent[] for the authenticated app. Handles CRUD via /api/events. Keeps local state in sync after mutations to avoid unnecessary refetches.
🗓 schedules.ts — useSchedulesStore
Manages OfficeDuty[] schedules. Fetches from /api/duties. Used exclusively by ManageSchedulesPage.vue (super_admin only).
🏢 duties.ts — useDutiesStore
Manages the daily duty roster and attendance records. Fetches from /api/attendance/duty. Used by DutyCheckInPage.vue.

🔄 Composables

Reusable Composition API logic in src/composables/.

📍 useGeolocation.ts
Wraps browser Geolocation API. One-shot getPosition() and continuous startWatching()/stopWatching(). Reactive refs: latitude, longitude, accuracy, error. High accuracy, 10s timeout, 30s max cache age. Cleans up watcher on onUnmounted().
🖋 useOfflineQueue.ts
IndexedDB queue (via idb) for failed check-in/check-out requests when offline. Auto-flushes on window.online event. FIFO order is critical — checkouts sync after matching check-ins. Permanent 403 rejections are marked synced to stop retries.
🗺 useCampusGuide.ts
Provides campus building POI (points of interest) data for the Leaflet map in CampusGuidePage.vue.
📅 useEvents.ts
Fetches public event data for the public /events page. Reads from public/data/events.json — a static JSON file, NOT the Prisma API. Distinct from the useEventsStore Pinia store.

📱 PWA & Offline Support

The application is a full Progressive Web App, installable on Android and iOS.

Web Manifest
Name: University Student Council — ISUFST Dingle Campus
Short: USC ISUFST
Theme: #142850 (Navy)
Display: standalone
Icons: 192px and 512px PNG
Service Worker
Workbox with autoUpdate register type. Caches all JS/CSS/HTML/images/SVG up to 5 MB per file. Runtime caching for Supabase URLs: NetworkFirst strategy, 5 min TTL, 50 max entries.
Offline Queue
Failed check-ins during offline are stored in IndexedDB under store checkin-queue (DB v2). Auto-replayed in FIFO order when connectivity is restored.
QR Tokens Are Not Offline-Compatible QR tokens expire in 60 seconds and require a live session to generate. Do not attempt to cache or persist QR tokens. The offline queue handles check-ins, not QR generation.

All backend endpoints live in api/ as Vercel Serverless Functions. Every protected endpoint calls authenticate(req) first. All responses are JSON. All errors return { "error": "message string" }.

Auth — api/auth/

GET /api/auth/me Returns current user's Prisma profile

Auth: Any authenticated user  |  Returns: User

GET /api/auth/users List all users in the system

Auth: super_admin only  |  Returns: User[]

Events — api/events/

GET/api/eventsList all events, newest first

Auth: Any  |  Returns: USCEvent[]

POST/api/eventsCreate a new event

Auth: staff+  |  Body:

{ "title": string, "date": ISO8601, "lat": number, "lng": number, "radiusMeters": number }
GET/api/events/:idGet single event with attendance

Auth: Any  |  Returns: USCEvent with nested attendance[]

PUT/api/events/:idUpdate event details

Auth: staff+  |  Same fields as POST, all partial-update supported.

DELETE/api/events/:idDelete event and cascade attendance

Auth: super_admin

Attendance — api/attendance/

GET/api/attendance?eventId=:idAll attendance records for an event

Auth: Any  |  Returns: Attendance[] including user and recorder sub-objects

POST/api/attendanceRecord a check-in (event or duty)

Auth: Any (method restrictions apply)  |  Body:

{
  "type":     "event" | "duty",
  "eventId":  string,    // required if type="event"
  "dutyDate": ISO8601,   // required if type="duty"
  "userId":   string,    // officer being checked in
  "method":   "self" | "manual" | "qr",
  "lat":      number,    // required for method="self"
  "lng":      number     // required for method="self"
}
Server Validates Geofence for method=self Haversine distance is recomputed server-side. Cannot be bypassed from the client. Returns 403 if officer is outside event.radiusMeters.
Staff Cannot Manual-Record Their Own Attendance If method=manual and user.id === userId, returns 403. Prevents staff from overriding their own attendance record.
POST/api/attendance/checkoutRecord a check-out (sets checkOutAt)

Auth: Any (self) or staff+ (manual)  |  Body: { userId, eventId?, dutyDate? }

Duty checkouts enforce: nowManila >= orgProfile.dutyCheckOutStart. Returns 403 if too early.

POST/api/attendance/qrQR-based check-in (staff scans officer QR)

Auth: staff+  |  Body: Full QR token payload { userId, eventId, issuedAt, exp, sig }

Server re-computes HMAC-SHA256 and uses timingSafeEqual(). Tokens expire after 60 seconds.

GET/api/attendance/duty?date=ISO8601Duty roster + attendance for a date

Auth: Any  |  Returns: { duties: OfficeDuty[], attendance: Attendance[] }

POST/api/attendance/dutyRecord a duty check-in

Auth: Any  |  Validates officer has active duty schedule for today's day-of-week.

Enforces cutoff: nowManila < orgProfile.dutyCheckInCutoff. Returns 403 if too late.

GET/api/attendance/export?eventId=:idCSV export of event attendance

Auth: staff+  |  Response: text/csv attachment

Columns: Name, Position, Method, Latitude, Longitude, Recorded By, Checked In At, Checked Out At

🔒 Auth Layer

End-to-end authentication flow from browser to database.

Login Flow

1
Officer submits email + password on /login
Calls supabase.auth.signInWithPassword() via useAuthStore.login().
2
Supabase issues a JWT access token
Token stored in Supabase client memory/localStorage. SDK auto-refreshes before expiry.
3
fetchUser() calls GET /api/auth/me
Token sent as Authorization: Bearer <token>. API returns Prisma User record with role.
4
Router guard allows or redirects based on auth.user.role
All protected pages become accessible per the role's permissions.

API Token Verification Flow (api/_lib/auth.ts)

1
Extract Bearer token from Authorization header
Throws if missing or malformed.
2
Primary: supabaseAdmin.auth.getUser(token)
Uses service role key. On success, fetches matching Prisma User by Supabase UID.
3
Fallback: JOSE JWT verification (HS256)
Uses SUPABASE_JWT_SECRET. Handles transient Supabase errors gracefully.
4
Return AuthUser to handler
All handlers then call requireStaff(user) or requireSuperAdmin(user) as needed.

📷 QR Check-in System

Short-lived HMAC-SHA256 signed tokens that cannot be forged or reused.

Token Generation — src/lib/qr.ts
Uses browser crypto.subtle (WebCrypto API) with HMAC-SHA256.

Payload: { userId, eventId, issuedAt, exp, sig }
TTL: 60 seconds from issuedAt
Sign string: "userId:eventId:issuedAt"
Secret source: VITE_QR_SECRET env var
Token Verification — api/attendance/qr.ts
Uses Node.js crypto.createHmac('sha256', SECRET).

Re-computes expected signature. Uses timingSafeEqual() to prevent timing attacks. Checks now > exp for expiry.
Secret source: QR_SECRET env var (must match frontend)
QR_SECRET Must Match Both Environments Frontend uses VITE_QR_SECRET. Backend uses QR_SECRET. Both must be set to the same value. Mismatch causes all QR scans to fail with 403. 
// Full QR check-in flow
Officer on /qr  
  → generateQRToken(userId, eventId)  
  → QR canvas displayed (refreshes every 60s)

Staff on /scan  
  → html5-qrcode decodes camera frame  
  → POST /api/attendance/qr { userId, eventId, issuedAt, exp, sig }  
  → Server: timingSafeEqual(recomputed sig, provided sig)  
  → Server: now <= exp check  
  → 201 OK | 403 Forbidden

✓ Check-in Flows

The three check-in methods and their complete server-side validation chains.

Method 1: Self Check-in (Geolocation)

1
Officer opens /check-in or /check-in/:eventId
Selects event or arrives at pre-selected event page.
2
Browser requests GPS via useGeolocation.getPosition()
High accuracy, 10s timeout. User must grant location permission in browser.
3
POST /api/attendance with method: "self" + coordinates
Bearer token passed as Authorization header.
4
Server: Haversine distance vs event.radiusMeters
403 if too far. Client coordinates are untrusted; always recomputed server-side.
5
Server: Duplicate check for open record
409 if already checked in. Race condition protected by Prisma P2002 unique constraint catch.
6
201 Created
On network failure, useOfflineQueue stores payload in IndexedDB and retries on reconnect.

Method 2: QR Scan

1
Officer opens /qr
generateQRToken(userId, eventId) runs. 60s TTL. QR displayed as canvas.
2
Staff opens /scan — camera activates via html5-qrcode
Continuous scan loop until a valid QR is detected.
3
QR decoded → JSON token payload extracted
4
POST /api/attendance/qr with full token
Staff's Bearer token as auth header, not the officer's.
5
Server: HMAC-SHA256 re-sign + timingSafeEqual
403 on signature mismatch or expired token.
6
201 Created with method: "qr"

Method 3: Manual Override (Staff)

1
Staff on event detail page selects officer from roster
Manual controls are only visible to staff/super_admin.
2
POST /api/attendance with method: "manual" — no coordinates
3
Server: requireStaff(user)
403 if calling user has client role.
4
Server: self-targeting guard
403 if user.id === userId. Staff cannot manually record their own attendance.
5
201 Created. recordedBy always set to authenticated caller ID
Full audit trail. recordedBy is never accepted from client input.

📐 Conventions & Rules

Standards every developer must follow. Non-negotiable.

Vue Components
Always <script setup lang="ts">. No Options API. No defineComponent(). PascalCase filenames. Pages suffixed Page.vue.
Pinia Stores
Composition style: defineStore('id', () => {}). Located in src/stores/. Named useXxxStore.
API Handlers
Every handler starts with authenticate(req). Errors with "Access denied" → 403. All other unhandled → 500. No raw SQL.
Security Invariants
Never trust recordedBy from client. Always set recordedBy = user.id. Never skip authenticate(). Never trust client lat/lng for geofence.
Timezone Rule
UTC stored in DB always. Duty time-window checks use Manila TZ via Intl.DateTimeFormat('en-GB', { timeZone: 'Asia/Manila' }). The manilaHHMM() helper — extract to _lib/ if needed in a third handler.
No Over-Engineering
This is a lean org project. No middleware chains, no DI frameworks, no abstract service classes. Each API file is a single handler. Keep it simple.
Known Technical Debt to Address manilaHHMM() is duplicated in api/attendance/checkout.ts and api/attendance/duty.ts. If a third handler needs it, extract to api/_lib/time.ts.
The Haversine formula also exists in both api/attendance/index.ts (server) and src/lib/haversine.ts (client). This duplication is acceptable as the runtimes are isolated.

## ARCHITECTURE OVERVIEW

Single Vercel deployment. Vue SPA handles routing. API routes at /api/* are Vercel Serverless Functions.

Auth flow: Supabase Auth issues JWTs → frontend passes Bearer token → api/_lib/auth.ts validates via supabaseAdmin.auth.getUser() (with jose HS256 fallback) → looks up Prisma User record → returns AuthUser to handler.

Database: Supabase-managed PostgreSQL. Prisma manages the schema (prisma/schema.prisma). RLS is INTENTIONALLY DISABLED on all Prisma tables — the service-role connection bypasses it. All access control is code-level in API handlers.

The User.id in Prisma must exactly match auth.users.id in Supabase — this is the identity bridge.

## ROLES AND ACCESS CONTROL

Three roles enforced SERVER-SIDE only. Frontend guards are UX convenience, not security.

- **super_admin**: Full access. Manage users, events, duty schedules, org profile. Manual override for all.
- **staff**: Create/edit events. Manual override for others. QR scanner. CSV export. Cannot self-record via manual.
- **client**: Self check-in (geolocation). Own QR generation. Duty check-in if scheduled. View dashboard only.

Key guards:
- `requireStaff(user)` — requires super_admin or staff role
- `requireSuperAdmin(user)` — requires super_admin only
- Staff cannot manually record their own attendance (if method=manual AND user.id===userId → 403)
- `recordedBy` is ALWAYS set to the authenticated API caller, never from client input

## CHECK-IN METHODS

1. **Self (geolocation)**: Officer submits lat/lng → server recomputes Haversine distance vs event.radiusMeters → 403 if outside fence. Offline: stored in IndexedDB queue via useOfflineQueue composable, replayed on reconnect.

2. **QR Scan**: Officer generates 60-second HMAC-SHA256 token at /qr (using VITE_QR_SECRET + WebCrypto). Staff scans at /scan → POST /api/attendance/qr → server re-signs + timingSafeEqual() compare (using QR_SECRET). Tokens have 60s TTL.

3. **Manual override**: Staff selects officer from roster → POST /api/attendance with method=manual. Server calls requireStaff() and checks user.id !== userId guard.

## CONVENTIONS (STRICT — DO NOT DEVIATE)

1. Always `<script setup lang="ts">` in Vue files. Never Options API.
2. Pinia stores: Composition style defineStore('id', () => {}). Never Options style.
3. Every API handler calls authenticate(req) as the FIRST statement.
4. recordedBy is always set server-side from the authenticated user — never from client body.
5. Never bypass or soften authentication checks.
6. Never add Supabase RLS policies to Prisma-managed tables.
7. All duty time comparisons use Manila timezone (Asia/Manila) via Intl.DateTimeFormat.
8. UTC stored in DB — display conversion happens in the frontend.
9. No raw SQL in handlers — use Prisma client.
10. No over-engineering: no DI containers, no abstract service layers, no middleware chains. Keep it lean.
11. VITE_QR_SECRET (frontend) must match QR_SECRET (backend) — both are required in .env.
12. SUPABASE_SERVICE_ROLE_KEY must NEVER be prefixed with VITE_ or exposed to the browser.
