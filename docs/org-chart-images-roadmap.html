Architecture — How Profile Images Flow

Current State

The OfficerCard component already supports an optional photo prop. When provided, it renders the officer's image. When absent, it falls back to an SVG silhouette bust. Currently, none of the 30 officers have a photo assigned — all render the silhouette.

Each officer card shows an anonymous SVG head-and-shoulders silhouette. No identity, no personality.

After (Target)

Each officer card shows a crisp WebP portrait photo loaded from Supabase Storage's profiles bucket.

Phase 1 — Image Preparation

Collect & Convert Photos to WebP

Naming Convention Critical

Each photo filename must map to the officer it represents. Use a consistent, URL-safe naming scheme based on the officer's surname (lowercase, hyphenated).

Fig 2. Naming convention: officer's surname in lowercase + .webp extension

Image Specifications Requirements

  • Format: WebP (for faster loading in this CSR thick-client app)
  • Dimensions: 200 × 200 pixels (square, the card displays at ~46–50px CSS)
  • Quality: 85 (the project's standard — see scripts/convert-images.py)
  • Background: Neutral or transparent — portrait-style, head-and-shoulders crop
  • Max file size: Under 100 KB each (WebP at 200px is typically 15–40 KB)
  • Color profile: sRGB

WebP Conversion Script Available

The project already has a Python conversion script at scripts/convert-images.py. You can adapt it or use one of the manual methods below.

Option A — Online Converter (Easiest)
  1. Go to squoosh.app or convertio.co
  2. Upload each officer's photo
  3. Set output format to WebP, quality to 85, resize to 200×200
  4. Download and rename using the naming convention above
Option B — Python Script (Batch)

Use this script to batch-convert all photos in a folder:

Python — convert-officer-photos.py
from PIL import Image import os INPUT_DIR = "raw-photos" # folder with original JPG/PNG OUTPUT_DIR = "webp-photos" # folder for converted WebP SIZE = (200, 200) QUALITY = 85 os.makedirs(OUTPUT_DIR, exist_ok=True) for f in os.listdir(INPUT_DIR): if not f.lower().endswith(('.jpg', '.jpeg', '.png')): continue img = Image.open(os.path.join(INPUT_DIR, f)) img = img.convert("RGBA" if img.mode in ("LA", "RGBA", "PA") else "RGB") img = img.resize(SIZE, Image.LANCZOS) name = os.path.splitext(f)[0].lower().replace(" ", "-") out = os.path.join(OUTPUT_DIR, f"{name}.webp") img.save(out, "webp", quality=QUALITY, method=6) print(f"Converted: {f} → {os.path.basename(out)}")
Option C — PowerShell (Windows, using ffmpeg)

If you have ffmpeg installed:

# Convert a single image ffmpeg -i raw-photos\siason.jpg -vf "scale=200:200" -quality 85 webp-photos\siason.webp # Batch convert all JPGs in a folder Get-ChildItem raw-photos\*.jpg | ForEach-Object { $name = $_.BaseName.ToLower() -replace ' ','-' ffmpeg -i $_.FullName -vf "scale=200:200" -quality 85 "webp-photos\$name.webp" }
💡
Why WebP? WebP provides 25–35% smaller file sizes than JPEG at equivalent quality. Since this is a CSR thick-client app, faster image loading directly improves perceived performance and the PWA caches WebP files via Workbox.

Phase 2 — Storage Upload

Push WebP Files to Supabase Storage

Storage Bucket Info

The profiles bucket is already configured in Supabase Storage. It's a public bucket with a 5 MB file size limit, accepting PNG, JPEG, WebP, GIF, and AVIF MIME types.

Fig 3. Two upload methods: Supabase Dashboard (drag & drop) or PowerShell script (automated)

Option A — Supabase Dashboard (Recommended) Manual

Step-by-step Instructions
  1. Open the Supabase Dashboard and select your project
  2. Navigate to Storage in the left sidebar
  3. Click on the profiles bucket
  4. Click "Upload file" or drag all 30 WebP files at once
  5. Wait for all uploads to complete — each file should show a green checkmark
  6. Verify by clicking any file — copy the public URL and open it in a new tab
💡
Tip: Upload all files in a single batch. The dashboard supports multi-file drag & drop. This is the fastest method for a one-time setup of 30 small images.

Option B — PowerShell Upload Script Automated

The project includes scripts/upload-to-supabase.ps1 which reads credentials from .env and uploads files via the Supabase REST API.

PowerShell — Upload all officer photos
# Navigate to project root cd S:\Dev\Vue\usc-attendance # Upload a single file .\scripts\upload-to-supabase.ps1 ` -FilePath "webp-photos\siason.webp" ` -Bucket "profiles" # Upload all WebP files in the folder .\scripts\upload-to-supabase.ps1 ` -FilePath "webp-photos\*.webp" ` -Bucket "profiles"
⚠️
Prerequisite: Make sure your .env file has valid SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY values. The service role key is required for uploads (the anon key won't work).

Public URL Format

After upload, each photo is accessible at this URL pattern:

# URL pattern https://lqzrraggcaczwwohbqcb.supabase.co/storage/v1/object/public/profiles/FILENAME.webp # Examples https://lqzrraggcaczwwohbqcb.supabase.co/storage/v1/object/public/profiles/siason.webp https://lqzrraggcaczwwohbqcb.supabase.co/storage/v1/object/public/profiles/demonteverde.webp https://lqzrraggcaczwwohbqcb.supabase.co/storage/v1/object/public/profiles/depositario.webp
✅
Verification: Paste any URL into your browser. You should see the image render. If you get a 404, check that the filename matches exactly (case-sensitive).

Phase 4 — Component Wiring

Pass photo Prop in OrgChart.vue

Fig 5. Before and after: adding the :photo binding to each OfficerCard instance

What to Change Code Edit

Open src/components/ui/OrgChart.vue. There are 27 <OfficerCard> instances. Add the :photo prop to each one, pulling the value from the corresponding officer computed ref.

Vue — src/components/ui/OrgChart.vue (example change)
<!-- BEFORE --> <OfficerCard :name="president.name" designation="University President" :initials="getInitials(president.name)" variant="institutional" /> <!-- AFTER — add :photo binding --> <OfficerCard :name="president.name" designation="University President" :initials="getInitials(president.name)" variant="institutional" :photo="president.photo" />
💡
Safe rollout: Since photo is optional (photo?: string), adding the prop binding is safe even before all photos are uploaded. Officers without a photo URL will continue showing the SVG silhouette fallback.

Phase 5 — Verification

Test, Polish & Troubleshoot

Verification Checklist Manual

  • Open /officers page — all 30 cards should show photos instead of silhouettes
  • Check each tier visually: admin (navy-gold), federated (deeper navy), advisers, executive (bright gold), senate (teal-steel)
  • Verify images are not stretched or cropped badly — they use object-fit: cover
  • Test on mobile — the chart auto-scales via CSS transform; images should remain crisp
  • Check browser DevTools Network tab — images should load as WebP (not PNG/JPEG)
  • Verify PWA caching — after first load, images should be served from Service Worker cache
  • Test with slow throttling (3G) — WebP files should load reasonably fast (15–40 KB each)
  • Run npm run build — confirm no build errors related to the photo URLs

Run the Dev Server Command

# Start dev server npm run dev # Open in browser # http://localhost:5173/officers

Troubleshooting

⚠️
Image not showing (silhouette still visible)?
Check that the photo URL in officers.ts is correct. Open the URL directly in a browser tab. Common issues: typo in filename, wrong case (Siason.webp vs siason.webp), file not uploaded yet.
⚠️
Image shows but is stretched/squished?
The OfficerCard uses object-fit: cover which crops to fill the square. Make sure source photos are roughly square or center-weighted portraits.
⚠️
CORS error in console?
Supabase Storage public buckets include CORS headers by default. If you see CORS errors, check that the bucket is set to public: true in the Supabase Dashboard → Storage → profiles → Settings.
⚠️
403 Forbidden on image URL?
The bucket policies may not be set correctly. Re-run the policies section of scripts/setup-supabase-storage.sql or check that the "Public read profiles" policy exists.
💡
Want to test with one photo first?
Upload just one photo (e.g., siason.webp), add the photo URL only to the President's entry in officers.ts, and add :photo="president.photo" only to the first OfficerCard in OrgChart.vue. Verify it works, then do the rest.

Performance Notes

  • File sizes: WebP at 200×200, quality 85 typically produces 15–40 KB files. 30 photos ≈ 0.5–1.2 MB total.
  • PWA caching: Workbox is configured to precache all *.webp files. After first visit, images load from Service Worker cache.
  • Supabase CDN: Supabase Storage serves files from a CDN edge node closest to the user (region: ap-northeast-1).
  • Rendered size: The OfficerCard avatar is ~46–50px CSS. The 200px source provides 4× resolution for retina displays.
  • No lazy loading needed: With only 30 small WebP images, eager loading is fine. The total payload is smaller than a single hero image.
