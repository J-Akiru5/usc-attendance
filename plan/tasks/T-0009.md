---
id: T-0009
title: Photo evidence for manual check-ins, with a retention rule
milestone: M-0001
priority: '1'
status: ready
rev: 1
objective: Let an officer attach a photo of the student ID when a manual check-in is recorded, store it privately, and delete it on a fixed schedule, so the one attendance path that bypasses the scanner leaves evidence a reviewer can check.
outcome: A manual entry can carry a photo of the ID; the photo is private, readable only by staff, audited on read, and deleted after the retention window without touching the attendance row.
verification_profile: code
integration_target: develop
deployment_impact: code
deployment_verification: Local gates plus CI; storage and retention are verified with throwaway data in the dev database, never by deploying.
dependencies: []
ownership:
  - server/api/attendance/**
  - server/utils/attendance-photo.ts
  - server/utils/retention.ts
  - app/pages/scan.vue
  - app/utils/scan-queue.ts
  - prisma/migrations/*_attendance_photo/**
  - prisma/schema.prisma
  - tests/unit/attendance-photo.test.ts
  - scripts/e2e/scan-integrity.e2e.mts
  - scripts/e2e/retention.e2e.mts
out_of_scope:
  - Face recognition or any biometric matching
  - Photos on QR or self check-ins
interfaces:
  - POST /api/attendance accepts a photo reference for manual entries only
  - GET the photo back only for staff, audited
  - the retention job deletes expired photos and records the count
deliverables:
  - additive migration for the photo key, captured time and expiry on attendance
  - private storage write with a size and type guard, refused for non-manual methods
  - staff-only read through the authenticated route, audited as a sensitive read
  - retention purge wired into the existing purge job, with the count audited
  - UI capture in the manual fallback, queued offline like the scan itself
acceptance:
  - 'AC1 [test]: a manual entry with a photo stores a private key and returns no public URL'
  - 'AC2 [test]: a photo read by a student or anonymous caller is refused, and a staff read is audited'
  - 'AC3 [test]: the retention job deletes an expired photo and leaves the attendance row intact'
  - 'AC4 [cmd]: npx eslint . && npm run typecheck && npm run typecheck:legacy && npx vitest run'
constraints_security:
  - Photos are private objects; no public bucket, no permanent URL.
  - A photo is evidence of identity and is never returned in any list or export.
constraints_compatibility:
  - Manual entries without a photo stay valid; existing rows need no backfill.
  - The default retention is 90 days and is configurable in one place.
database_migration: additive
escalation:
  - If the storage provider cannot enforce private access, stop before writing any photo.
---

# Notes

Owner decision recorded on 2026-10-20: manual check-ins carry a reason and a photo of the ID. This
introduces a new category of personal data, so the retention window and the privacy notice (council
answer C-5) must name it before cutover.
