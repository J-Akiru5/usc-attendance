---
id: T-0006
title: BC-5 - both scan timestamps, per-scan idempotency, and a reason for manual entries
milestone: M-0001
priority: '1'
status: ready
rev: 1
objective: Record both the moment a scan happened on the device and the moment the server accepted it, make every scan idempotent with a client-generated key, and require a reason when a student is checked in by hand.
outcome: A retried or replayed scan cannot double-record attendance, a dispute can be settled from the two timestamps, and every manual check-in carries the officer reason that justified it.
verification_profile: code
integration_target: develop
dependencies: []
ownership:
  - server/api/attendance/**
  - server/utils/attendance.ts
  - app/pages/scan.vue
  - app/composables/useScanQueue.ts
  - app/utils/scan-queue.ts
  - prisma/migrations/*_scan_integrity/**
  - prisma/schema.prisma
  - tests/unit/scan-integrity.test.ts
  - scripts/e2e/scan-integrity.e2e.mts
  - scripts/e2e/run.mts
out_of_scope:
  - Changing the scanner hardware or the QR format
  - Any change to the frozen public site
interfaces:
  - POST /api/attendance accepts an idempotencyKey and a scannedAt from the device
  - Manual check-in requires a reason
deliverables:
  - additive migration adding scannedAt, idempotencyKey and manualReason with a unique index on the key
  - pure decisions in a util, unit-tested
  - route honours a replay by returning the original record instead of writing twice
  - scanner sends both times and a stable key per scan
  - live suite registered in the runner
acceptance:
  - 'AC1 [test]: replaying the same key returns the first record and writes no second attendance row'
  - 'AC2 [test]: a device clock that is ahead is stored but the server time remains the authority'
  - 'AC3 [test]: a manual check-in without a reason is refused, and with one is audited'
  - 'AC4 [cmd]: npx eslint . && npm run typecheck && npm run typecheck:legacy && npx vitest run'
constraints_security:
  - The idempotency key is opaque and carries no student data.
  - A replay by a different officer must not read back the first officer record.
constraints_compatibility:
  - Existing attendance rows keep working with null device times.
  - Additive migration only; schema.prisma and scripts/e2e/run.mts are shared and integrated serially.
database_migration: additive
escalation:
  - If the existing scanner cannot generate a stable key without changing the QR payload, stop and propose the smallest compatible mechanism.
